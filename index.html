Architecture

How it's built

Frontend and backend are on separate platforms, with Vercel proxying all API and auth calls so session cookies stay first-party.

Vercel (React/Vite) ── /api, /auth ──▶ Render (Express) ── pg ──▶ Neon (Postgres)
└── proxies ──▶ Anthropic Claude API
The browser only ever talks to the Vercel origin. /api and /auth are proxied server-side so the session cookie is first-party — no third-party cookie issues across browsers with default settings. The backend holds all secrets (Claude key, OAuth credentials) and never exposes them to the client.
How Claude is used

Six distinct AI workflows

Claude is called from a secure backend proxy — the API key never touches the browser.

Streaming
Bullet & cover letter generation
Streams tokens directly to the UI as they arrive, so output feels instant. Uses the full resume store as context for every prompt.
Structured JSON
Keyword matching & resume scoring
Prompts return strict JSON (matched/missing keywords, scores, feedback) parsed and rendered as interactive UI elements.
Agentic edit
Auto-tailor resume
Claude rewrites the summary and skills to include missing JD keywords, then updates the Zustand store directly — no copy-paste needed.
Personalized
Interview prep
Full resume text is injected into the prompt so questions are tailored to the candidate's actual background, not generic templates.

Reflection

What I learned

"The hardest part wasn't the AI integration — streaming Claude responses into a React UI is surprisingly clean. The real work was the deployment architecture: getting session cookies to work first-party across Vercel and Render required understanding SameSite cookie policies, Render's reverse proxy headers, and ultimately proxying auth through Vercel. The lesson: cross-origin auth is a solved problem, but only if you know which layer to solve it at."
